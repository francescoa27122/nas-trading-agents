# Code of Conduct

## The short version

Be straightforward and be kind. Criticise code, not people. Assume the person
on the other end is competent and acting in good faith until you have real
evidence otherwise.

## Expected

- **Technical directness is welcome.** "This is wrong, and here is the input
  that breaks it" is a good comment. Bluntness about code is not rudeness.
- **Disagree with reasons.** If you think a decision is wrong, say why and show
  the derivation. Changing a position because new evidence arrived is good
  practice; changing it because someone was annoyed is not.
- **Report what you actually observed**, including when it contradicts what you
  hoped. Failures reported as failures are more useful than optimistic
  summaries.
- **Respect that maintainer time is finite.** This is a personal project. A
  slow response is not a slight.

## Not acceptable

- Personal attacks, insults, or making someone's identity the subject
- Harassment of any kind, public or private
- Sexualised language or imagery
- Publishing others' private information without permission
- Sustained disruption of discussions
- Deliberately wasting maintainer time — including bad-faith reports, spam
  pull requests, and AI-generated submissions the sender has not read or run

## Scope

Applies in issues, pull requests, discussions, commit messages, and any space
where you are representing this project.

## Enforcement

Report to the repository owner through GitHub private security reporting or a
direct message. Reports are handled confidentially.

Responses, in escalating order: a private word, an edited or removed comment, a
temporary block, a permanent block. The maintainer's decision is final.

Something can be within the letter of these rules and still make people not
want to participate. That is also grounds for action.
